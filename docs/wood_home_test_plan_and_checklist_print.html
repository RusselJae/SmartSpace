Appendix A — System checklist

Tester: _______________________________    Date: _______________________________

Mark each item when verified. Expected results describe correct behavior for Wood Home / SmartSpace.

A. Account management

Customer (storefront)

  • Enter valid registration data (email, names, DOB, username, password, confirm, terms/privacy). Expected: Submit succeeds; account created; verification path offered.
  • Submit registration with duplicate email. Expected: Clear “email already taken” (or equivalent).
  • Sign in with valid credentials. Expected: Main app shell loads; personalized data loads.
  • Sign in with wrong password. Expected: Error message; no partial auth state.
  • Forgot password flow end-to-end. Expected: Reset completes; new password works.
  • Edit profile and save. Expected: Changes persist on reopen.
  • Add default shipping address. Expected: Checkout can pre-fill; single default enforced.

Administrator (console)

  • Wrong admin email/password. Expected: Incorrect-credentials message; remain on login.
  • Valid admin credentials. Expected: Redirect to admin Dashboard (not storefront).
  • Open Users. Expected: List loads for permitted role; forbidden otherwise.
  • Open Admins / Activity Logs as super admin. Expected: Data visible; restricted for others where applicable.
  • First-server bootstrap admin (if applicable). Expected: First admin is super_admin; later invites obey role rules.

B. Product catalog

Customer

  • Catalog home loads. Expected: Products and images load without unexplained blank state.
  • Product detail. Expected: Price, stock, description match admin/API.
  • Wishlist add/remove. Expected: Consistent after refresh or restart if server-backed.

Administrator

  • Create minimal product. Expected: Visible in API and storefront after refresh.
  • Set stock to zero. Expected: Buy/add blocked with stock messaging on user side.
  • Attach 3D model path + scale. Expected: Admin preview renders; user AR entry when intended.

C. Commerce

Customer

  • Guest vs signed-in cart rules. Expected: Match policy (e.g. checkout requires sign-in).
  • PayMongo happy path. Expected: Return URL handled; order/payment state correct.
  • Upload payment proof. Expected: File tied to order; success feedback in UI.
  • Cancel within configured minutes. Expected: Order shows cancelled; inventory policy honored.

Administrator

  • Change order status. Expected: User Orders reflects new status after refresh.
  • Confirm payment / review proof. Expected: No unsafe double-confirmation.
  • Settings: cancellation window. Expected: User cancel affordance matches minutes setting.

D. AR visualization

Customer

  • Launch AR from product with model. Expected: Placement on supported Android; sensible fallback elsewhere.
  • 3D-only rotate/zoom. Expected: Smooth interaction; no hard errors in logs.

Administrator

  • Broken modelPath. Expected: Error or placeholder; not infinite spinner.

E. Support & engagement

Customer

  • Send support message. Expected: Appears in admin Support inbox.
  • Submit review. Expected: Pending until moderated if applicable.

Administrator

  • Reply in Support. Expected: Customer sees reply; unread badge updates.
  • Reject or delete abusive review. Expected: Removed from public product reviews.
